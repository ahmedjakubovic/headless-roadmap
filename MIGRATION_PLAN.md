# Migration Plan: Vite + React → TanStack Start (+ Prisma/SQLite)

> **Status: COMPLETED — migration executed and verified.**
> Branch: `tanstack-start-migration`

## 1. Current state (inspected)

- **Build:** Vite 8.3.0 (rolldown-based), `@vitejs/plugin-react` 6.1.1 + `@rolldown/plugin-babel` with `reactCompilerPreset` (React Compiler)
- **UI:** React 19.2.8, Tailwind CSS 4.3.3 (`@tailwindcss/vite`), shadcn/ui components in `src/components/ui/` (relative imports, **no** path alias, no `components.json`)
- **Entry:** `index.html` → `src/main.tsx` → `src/App.tsx` (mock products, cart state, filters, search, wishlist — all client state)
- **CSS:** `src/index.css` with `@import "tailwindcss";` + custom global styles
- **TS:** TypeScript ~6.0.2, project references (`tsconfig.app.json` / `tsconfig.node.json`), `verbatimModuleSyntax: true`
- **Environment:** Node v24.13.0, pnpm 10.30.3 (repo currently ships a `package-lock.json`; migrating to pnpm — see §4/§5)
- shadcn/ui usage is plain component files — nothing Vite-specific; moves over untouched.

## 4. File changes

### Delete
- `index.html` — replaced by the root route's document shell
- `src/main.tsx` — Start provides its own client/server entries
- `src/App.tsx` — content moved verbatim into `src/routes/index.tsx`
- `package-lock.json` — replaced by `pnpm-lock.yaml` when switching package managers

### Create
- `src/router.tsx` — `getRouter()` → `createRouter({ routeTree, scrollRestoration: true })`
- `src/routes/__root.tsx` — `<html>`/`<body>` shell with `HeadContent`, `Outlet`, `Scripts`; `head()` carries over title/meta/favicon from `index.html` + stylesheet link
- `src/routes/index.tsx` — the existing `App` component (mock data, state, effects, `TooltipProvider`) moved **unchanged**, exported via `createFileRoute('/')`
- `src/routeTree.gen.ts` — auto-generated on first `dev`/`build` (not handwritten)
- `prisma/schema.prisma` — via `prisma init` + a `Product` model mirroring the mock data shape (foundation only)
- `prisma7.config.ts` — generated by `prisma init` (v7 config file)
- `.env` — `DATABASE_URL="file:./dev.db"` (gitignored)
- `generated/prisma/` — ESM Prisma Client output (gitignored)
- `src/lib/prisma.ts` — `PrismaClient` singleton via `PrismaBetterSqlite3` adapter. **Not imported by any UI code yet** — the Products page keeps rendering mock data.
- `pnpm-lock.yaml` — generated by the first `pnpm install`

### Modify
- `vite.config.ts` — add `tanstackStart()` plugin **before** `viteReact()` (required order per docs); keep `tailwindcss()` and the React Compiler babel pass
- `package.json` — scripts: `"dev": "vite dev"`, `"build": "vite build"`; add `"typecheck": "tsc -b"`; drop `preview` (Start builds a Node server bundle to `.output/`, `vite preview` no longer applies); add `"packageManager": "pnpm@10.30.3"`; add `"pnpm": { "onlyBuiltDependencies": ["@prisma/client", "@prisma/engines", "better-sqlite3", "prisma"] }` so pnpm 10 is allowed to run their native/engine build scripts
- `tsconfig.app.json` — set `verbatimModuleSyntax: false` (official Start recommendation; can otherwise leak server code into client bundles)
- `.gitignore` — add `.env`, `*.db*`, `generated/`, `.output/`, `.tanstack/`
- `eslint.config.js` — ignore `.output`, `generated`, `src/routeTree.gen.ts` (generated files); no other lint changes

## 5. Step-by-step execution (after approval)

0. `pnpm install` — installs the existing dependencies (repo has none installed yet) and creates `pnpm-lock.yaml`
1. `pnpm add @tanstack/react-start @tanstack/react-router @tanstack/react-pacer @tanstack/react-hotkeys`
2. `pnpm add @prisma/client@^7.10.0 @prisma/adapter-better-sqlite3 dotenv` and `pnpm add -D prisma@^7.10.0 @types/better-sqlite3`
3. `pnpm approve-builds` (or rely on the `pnpm.onlyBuiltDependencies` allowlist from §4) so the `better-sqlite3`/`prisma` build scripts actually run
4. Remove `package-lock.json` (pnpm is now the package manager of record)
5. Rewrite `vite.config.ts` (add `tanstackStart()` before `viteReact()`)
6. Update `package.json` scripts/config, `tsconfig.app.json`, `.gitignore`, `eslint.config.js`
7. Create `src/router.tsx`, `src/routes/__root.tsx`, `src/routes/index.tsx`; delete `index.html`, `src/main.tsx`, `src/App.tsx`
8. `pnpm exec prisma init --datasource-provider sqlite --output ../generated/prisma`, add `Product` model, `pnpm exec prisma migrate dev --name init` (creates `dev.db` + generates client), add `src/lib/prisma.ts`
9. Install Pacer + Hotkeys as dependencies only — do NOT wire any behavior (see §6)
10. Verify (see §7), fix any issues, commit on the `tanstack-start-migration` branch with plain git (message proposal: `feat: migrate from Vite to TanStack Start with Prisma/SQLite foundation`)

## 6. Pacer & Hotkeys: install only — do NOT change behavior

- **Pacer (`@tanstack/react-pacer`) and Hotkeys (`@tanstack/react-hotkeys`) are added as dependencies only.**
- **Do NOT debounce/throttle existing handlers and do NOT register any keyboard shortcut** unless the original app already had one. This app had neither, so there is no `useDebouncedValue` and no `useHotkey` call anywhere in `src/`.
- The original app filtered products instantly on every keystroke and had no keybinds; that behavior is preserved exactly.
- An earlier pass added a 300 ms search debounce and a `Mod+K` shortcut; both were reverted (see §10, finding 12).
- No devtools panels added.

## 9. Caveats / risks

1. **`prisma` CLI tag trap:** the `latest` dist-tag for the `prisma` CLI currently points at `8.0.0-rc.15` (a release candidate), while `@prisma/client`'s `latest` is the stable `7.10.0`. Prisma requires matching CLI/client majors, and Prisma's own v7 quickstart installs `prisma@prev` (which resolves to 7.10.0) for exactly this reason — so we pin `prisma@^7.10.0`.
2. **`better-sqlite3` is a native module, and pnpm 10 blocks build scripts by default** — pnpm 10 will not run `better-sqlite3`/`prisma` install scripts unless approved (`pnpm approve-builds`, or the `pnpm.onlyBuiltDependencies` allowlist from §4). Without approval the SQLite adapter can fail at runtime. Node 24 prebuilds should avoid needing a full Windows toolchain build.
3. **SSR safety:** the app is SSR-rendered by Start. The only browser API used is `document.title` inside `useEffect` (client-only — safe). No render-time browser globals found.
4. **React Compiler babel plugin** is kept, but it's an extra transform in Start's plugin pipeline; if it conflicts, fallback is plain `viteReact()` (one-line change, noted not done preemptively).
5. **Tailwind `?url` stylesheet pattern** (documented) has a known issue only with Vite 8's `experimental.bundledDev` — we will not enable that flag.
6. **Dev port changes** 5173 → 3000 (Start default).
7. `routeTree.gen.ts` is generated; lint/gitignore handle it. Prisma Client v7 is generated to `generated/` (ESM-first `prisma-client` generator) — also gitignored.
8. ESLint `react-refresh` rule may flag `export const Route` in route files — if so, we add `allowExportNames` or a routes-only override (kept out unless it actually fires).

## 10. Execution findings (what actually happened)

Deviations and surprises encountered while executing this plan — the most useful part for the next migration:

1. **GitButler needed setup** — `but` refused until `but setup` was run (repo wasn't registered). That creates the `gitbutler/workspace` branch.
2. **Prisma CLI `latest` is a pre-release** — confirmed at install time: pnpm reported `prisma 7.10.0 (8.0.0-rc.15 is available)`. Pinning `prisma@^7.10.0` was correct.
3. **pnpm 10 blocks dependency build scripts** — `better-sqlite3` and `@prisma/engines` scripts are skipped unless allowlisted. The `pnpm.onlyBuiltDependencies` entry fixed it (both ran on install).
4. **`prisma init` installs agent "skills" scaffolding** — it created `.claude/`, `.windsurf/`, `.agents/`, and `skills-lock.json`. These were removed; delete them (or ignore them) too.
5. **ESLint fast-refresh rule can't be satisfied by `allowExportNames`** — `allowExportNames: ['Route']` did **not** silence `react-refresh/only-export-components`: when the only export is the non-component `Route` const, the plugin never detects a React export and flags the local route component. Turning the rule **off** for `src/routes/**` is the working fix.
6. **`routeTree.gen.ts` must exist before typecheck** — `createFileRoute('/')` and the `./routeTree.gen` import don't typecheck until the tree is generated. Run `vite dev`/`vite build` once first; the generated file was committed so a fresh `typecheck` works.
7. **Build output is `dist/`, not `.output/`** — this Vite-environments build emits `dist/client/*` + `dist/server/server.js`. `.output` is Nitro-only. `dist/server/server.js` is a **fetch-style handler, not a runnable server** (`node dist/server/server.js` exits immediately); `vite preview` is the documented local production preview. The original "drop `preview`" call was wrong and was corrected.
8. **`dev.db` lands in the project root** (resolved relative to `prisma7.config.ts`), not in `prisma/`.
9. **React Compiler babel pass works with Start** — no fallback to plain `viteReact()` needed; it's the slowest build hook but builds fine.
10. **Runtime Prisma verified** — a throwaway `tsx` script did create/read/delete against SQLite successfully (adapter + generated ESM client work at runtime, not just types).
11. **Environment, not migration:** port 3000 was already occupied, so Vite served on 3001.
12. **Scope correction after review:** the first pass added a `Mod+K` hotkey and a 300 ms search debounce. Both were *new behavior*, not migration. They were reverted; Pacer and Hotkeys remain installed but unused, so the migrated app is behavior-identical to the original.
